# 新排期格式说明

旧排期的问题：每天只写"看某网站某节 + 敲点什么"。知识点、判定标准、代码骨架全在你脑子外面，等于每天都在重新找资料。

新格式：每天一份独立文件，不依赖任何外部网站就能开工。

## 每天文件必须包含

1. **讲解**（主体）：每个概念按"是什么 → 为什么需要 → 可运行例子（带输出）→ 边界"写，不许只列结论。
2. **程序框架**：文件路径 + 函数签名 + 已写好的测试。你只填实现，不纠结目录结构。
3. **测试题**：可执行的测试（`node --test` 或 `vitest`），带预期输出，跑不通就是没学会。
4. **速查表**：当天内容的压缩版，用于第二天复习。
5. **常见坑**：3–5 条，错误写法和正确写法对照。
6. **验收线**：一句话，明确到什么程度算过。

硬性要求：

- **条目式讲解**：每条写成"**标签**：一句话说明"，独立成段，紧接着一个最小代码块（3–5 行），结果写在行尾注释里（`// x = 10`）。
- 不写长段落散文。单条说明不超过 2 行；超过就拆成两条。
- 代码块必须能直接复制粘贴运行，输出写在 `// →` 或行尾注释里。
- 对比类内容用表格，不用段落。
- 讲一个概念之前，先说清它解决什么问题；没有动机的概念一律删掉。
- **首次提及即定义（线性铁律）**：任何方法、语法、API，第一次出现的位置必须紧跟着它的定义、签名和最小例子。不许说"详见附录/后面会讲"。
- **没有学过的概念不许出现**：要么删掉，要么就地补一句最小定义。举例时不许用尚未教过的类型（比如还没教 `Map` 就拿 `Map` 举例）。
- **不设附录**：文末附录会让人跳读，已全部删除。所有定义只在正文出现，且只出现一次（重复提到时不再解释）。
- **每项必须有"真实项目里用在哪"一节**：至少 3 个真实场景，每个配最小代码，最后一句写"没有它会怎样"。纯语法条目也要给用途，不许只讲机制。
- **英文必须带中文**：引擎报错原文保留英文（无法翻译，且行号在原文里），但每一处后面必须紧跟一行 `// 中文：...`。代码注释一律用中文；标识符（变量名、函数名）保持英文。
- **出现新语法时，必须先解释语法本身**：先给"这个语法长什么样"（把每个符号拆开讲），再给例子。（解构、展开、`?.`、`??`、`Map`/`Set`、`class` 都踩过这个坑。）

## 目录

```
plan/
  README.md              本文件
  phase1/day05.md        第 1 阶段每天一份
exercises/
  day05/                 与当天任务一一对应的代码骨架 + 测试
```

## 运行

```bash
cd ~/code/fullstack-learning
npm run day5                     # 只跑 Day 5
npm test                         # 跑所有已交的测试
node --test "exercises/day05/*.test.mjs"   # 等价写法
```

测试一开始全是红的，这是正常的：你要做的是让它们变绿。

## 交付节奏（我写，你只验收）

不按日期交付，按内容批次交付：

| 批次 | 内容 | 状态 |
|------|------|------|
| 1 | Day 1–9 | 已交 |
| 2 | Day 10–14（事件循环 / 错误处理 / ESM / Git / 阶段验收） | 当前批次用完前交 |
| 3 | Day 15–21（TypeScript + Todo App 项目） | 同样规则 |

规则：你手里的材料还剩 2 项时，下一批必须已经躺在仓库里。不提前写太多，也不让你断粮。

不一次性写完 133 天，原因只有一个：现在写的第 90 天内容，等你用到时水平和需求都变了，写了也是废纸。
