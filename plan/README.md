# 新排期格式说明

旧排期的问题：每天只写"看某网站某节 + 敲点什么"。知识点、判定标准、代码骨架全在你脑子外面，等于每天都在重新找资料。

新格式：每天一份独立文件，不依赖任何外部网站就能开工。

## 每天文件必须包含

1. **讲解**（主体）：每个概念按"是什么 → 为什么需要 → 可运行例子（带输出）→ 边界"写，不许只列结论。
2. **程序框架**：文件路径 + 函数签名 + 已写好的测试。你只填实现，不纠结目录结构。
3. **测试题**：可执行的测试（`node --test` 或 `vitest`），带预期输出，跑不通就是没学会。
4. **速查表**：当天内容的压缩版，用于第二天复习。
5. **常见坑**：3–5 条，错误写法和正确写法对照。
6. **验收线**：一句话，明确到什么程度算过。

硬性要求：

- 代码块必须能直接复制粘贴运行，输出写在 `// →` 后面。
- 讲一个概念之前，先说清它解决什么问题；没有动机的概念一律删掉。
- 前后概念之间要有过渡句，不许从闭包直接跳到柯里化。

## 目录

```
plan/
  README.md              本文件
  phase1/day05.md        第 1 阶段每天一份
exercises/
  day05/                 与当天任务一一对应的代码骨架 + 测试
```

## 运行

```bash
cd ~/code/fullstack-learning
npm run day5                     # 只跑 Day 5
npm test                         # 跑所有已交的测试
node --test "exercises/day05/*.test.mjs"   # 等价写法
```

测试一开始全是红的，这是正常的：你要做的是让它们变绿。

## 交付节奏（我写，你只验收）

不按日期交付，按内容批次交付：

| 批次 | 内容 | 状态 |
|------|------|------|
| 1 | Day 1–9 | 已交 |
| 2 | Day 10–14（事件循环 / 错误处理 / ESM / Git / 阶段验收） | 当前批次用完前交 |
| 3 | Day 15–21（TypeScript + Todo App 项目） | 同样规则 |

规则：你手里的材料还剩 2 项时，下一批必须已经躺在仓库里。不提前写太多，也不让你断粮。

不一次性写完 133 天，原因只有一个：现在写的第 90 天内容，等你用到时水平和需求都变了，写了也是废纸。
