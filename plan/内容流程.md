# 内容流程（取代排期）

从 2026-11-06 起，不再按日历推进。唯一的进度单位是"内容项完成"，不是日期。

## 规则

1. **顺序推进**：Day 1 → 2 → … → 133，不许跳项（"快进"除外）。
2. **完成定义**：当天断言全绿 + `notes.md` 有记录 + 一次 commit。三者缺一不算完成。
3. **快进**：当天断言一次全绿且总用时 < 90 分钟 → 记为"快进完成"，直接进下一项。
4. **卡住处理**：同一项连续两个学习时段（8h）没变绿 → 停下来，把卡点写成一句话，把该项拆成"最小可过版本"（先让测试绿，再补理解），然后继续。不许在一项上无限空转。
5. **没有日期、没有周次、没有结束日**。任何人问"什么时候学完"，答案都是"按这个顺序做完为止"。
6. **交付节奏按内容批次**，不按日期：
   - 阶段 0（0-1 ~ 0-3）：已交
   - 阶段 0（0-4 ~ 0-9）：你做到 0-3 时交
   - 阶段 1（原 Day 1–9）：材料已写好，标记为暂停，阶段 0 全部完成后启用
   - 之后的阶段按同样规则，永远保证你手里还有至少 2 项没做的材料
7. Todoist 不再作为进度工具。旧 CSV 不再重生成，日期提醒全部作废。

## 进度查询

```bash
cd ~/code/fullstack-learning
npm run status    # 打印当前内容项、完成数、后面 3 项
```

数据在 `progress.json`。每完成一项，把该项 `status` 改成 `"done"`，`current` 改成下一项编号。

## 关于"每天 4 小时"

4 小时是单次学习时段的长度，不是日历承诺。今天只能学 2 小时就记 2 小时，进度按变绿的断言数算，不补"欠账天数" —— 因为没有天数这回事了。
